# Настройка входа в админку Garage Pro (один раз)

Админка подготовлена для Decap CMS + Netlify Identity + Git Gateway. Основной публичный сайт остаётся на Vercel. **До выполнения шагов ниже вход в админку не заработает**: адрес служебного сайта Netlify пока является заглушкой.

## Что настроено в проекте

- `/admin` открывает редактор Decap CMS на русском языке.
- Редактор показывает только коллекцию «Статьи»; удаление статей из интерфейса отключено.
- Дата называется `date`, как ожидает Astro.
- Фотографии загружаются в `public/assets/images/blog` и доступны по `/assets/images/blog/...`.
- Обложка статьи отображается на странице статьи и в списке блога.
- Конфигурация рассчитана на ветку GitHub `main`.

## Что нужно сделать после распаковки проекта

1. Создать в Netlify служебный сайт из того же GitHub-репозитория Garage Pro. Оставить команду сборки `pnpm run build` и папку публикации `dist` из `netlify.toml`.
2. В настройках этого сайта включить Identity и Git Gateway, если эти функции доступны для нового сайта в аккаунте Netlify. Подключить GitHub-репозиторий, где находится сайт.
3. Включить регистрацию по приглашению (не открытую регистрацию) и пригласить только адрес заказчика. Заказчик задаёт собственный пароль по приглашению.
4. Скопировать имя созданного сайта Netlify и заменить `YOUR-NETLIFY-SITE` в двух местах:
   - `public/admin/config.yaml` — в `identity_url` и `gateway_url`;
   - `public/admin/index.html` — в `APIUrl`.
5. Отправить изменения в ветку `main` GitHub. Vercel обновит публичный сайт; Netlify обновит служебный экземпляр.
6. Проверить на публичном адресе Vercel: `/admin` → вход заказчика → создание тестовой статьи с обложкой → публикация → появление статьи на сайте.
7. После проверки удалить тестовую статью из GitHub/редактора не нужно — удаление специально выключено в CMS. Для теста используйте черновой текст и не публикуйте его до полной проверки.

## Важные ограничения

- Нельзя гарантировать доступность Netlify Identity/Git Gateway для новых проектов, пока это не проверено непосредственно в аккаунте Netlify. Если функции недоступны, не пытайтесь обходить это случайными настройками: потребуется другой совместимый способ авторизации.
- Само создание аккаунта Netlify недостаточно: Identity и Git Gateway должны быть реально включены и связаны с нужным репозиторием.
- Не храните пароль заказчика в коде и не присылайте его в переписке. Пригласите пользователя по почте, чтобы он установил пароль сам.
- `netlify/functions/contact.mjs` не используется Vercel для формы обратной связи. Не меняйте существующий `api/contact.ts` при настройке CMS.
