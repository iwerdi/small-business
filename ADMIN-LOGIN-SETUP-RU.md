# Garage Pro: вход по логину и паролю для редактора

Этот вариант заменяет форму Sveltia CMS на простую собственную панель публикации. Клиенту не нужны GitHub и токен: он входит по логину/паролю, пишет статью и при необходимости загружает обложку. Серверная функция использует GitHub-токен из переменных окружения Vercel, создаёт Markdown-файл в `src/content/blog`, а Vercel автоматически собирает сайт после коммита.

## Важно

- Не удаляйте и не отзывайте текущий GitHub-токен, пока новая панель не проверена.
- Токен хранится только в Vercel Environment Variables. Не добавляйте его в `public/`, HTML, конфиги или GitHub.
- Для этого проекта нужно настроить переменные окружения и повторно задеплоить сайт.
- Код подготовлен, но в этой среде не удалось выполнить реальный деплой и проверить GitHub/Vercel интеграцию. Сначала протестируйте на черновой статье.

## Переменные окружения в Vercel

В Vercel откройте проект `garazh-pro` → Settings → Environment Variables. Добавьте все переменные для Production (и Preview, если нужно):

- `ADMIN_USERNAME` — придумайте отдельный логин для клиента, например не `admin`.
- `ADMIN_PASSWORD` — уникальный длинный пароль, минимум 16 символов; не используйте пароль от почты или других сервисов.
- `SESSION_SECRET` — случайная длинная строка, не менее 32 случайных символов. Её можно сгенерировать локально командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.
- `GITHUB_TOKEN` — fine-grained personal access token GitHub с доступом только к репозиторию `iwerdi/small-business` и разрешением **Contents: Read and write**. Metadata read-only оставьте по умолчанию. Установите срок действия и храните токен только в Vercel.
- `GITHUB_OWNER` — `iwerdi`.
- `GITHUB_REPO` — `small-business`.
- `GITHUB_BRANCH` — `main`.

После добавления или изменения переменных запустите Redeploy в Vercel.

## Проверка

1. Откройте `https://garazh-pro.vercel.app/admin/`.
2. Войдите с `ADMIN_USERNAME` и `ADMIN_PASSWORD`.
3. Создайте тестовую статью с уникальным названием и небольшой фотографией (до 3 МБ).
4. Нажмите «Опубликовать статью» и дождитесь сообщения об успешной отправке.
5. В GitHub проверьте, что появился Markdown-файл в `src/content/blog` и, если добавляли фото, файл в `public/assets/images/blog`.
6. Дождитесь зелёного статуса последнего деплоя Vercel и проверьте статью на сайте.

Если вход или публикация не работают, посмотрите текст ошибки на странице, а также Functions Logs в Vercel. Не отправляйте никому `GITHUB_TOKEN`, `ADMIN_PASSWORD` или `SESSION_SECRET`.

## Ограничения первой версии

- Это форма создания новых статей; редактирование и удаление существующих статей пока не добавлены.
- Можно загрузить одну обложку до 3 МБ. Встроенные изображения в тексте пока не загружаются через редактор.
- Серверная блокировка повторных попыток входа работает в пределах экземпляра функции; для более строгой защиты от перебора желательно добавить Vercel Firewall/WAF или внешнее хранилище лимитов.
- Фото и статья записываются отдельными коммитами, поэтому если второй шаг не пройдёт, фото может остаться в репозитории без статьи.
- Успешная запись в GitHub ещё не означает, что деплой завершился. Проверяйте статус Vercel.
